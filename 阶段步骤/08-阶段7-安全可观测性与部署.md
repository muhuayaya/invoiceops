# 阶段 7：安全、可观测性与部署

## 阶段目标

为 PoC 落实可兑现的最小安全控制、全链路观测与 Docker Compose 一键启动能力，并把关键故障降级路径做成可验证行为。

## 开始条件

- API、worker 与 web 至少具备可集成的最小版本。
- 真实企业数据尚未接入；本阶段仍只处理公开或模拟数据。

## 实施步骤

### 7.1 实现本地认证与权限矩阵（B）

使用 JWT 和本地种子用户提供 `admin`、`reviewer`、`observer` 三种角色。认证层应可在未来替换为 OIDC，但当前不扩展到企业 SSO。

**验收：**每个角色的允许和拒绝路径均有测试；授权失败也留下审计事件。

### 7.2 建立结构化日志与追踪（B）

让 `trace_id` 贯穿 API、worker、模型和审计。日志至少记录时间、级别、组件、追踪标识、版本、耗时和结果码，严禁写入正文、凭据或受保护字段。

**验收：**自动化扫描确认日志无工单原文、密钥或敏感字段。

### 7.3 提供健康检查与指标（B）

实现 `/healthz`、`/readyz` 和 Prometheus 指标。存活检查只表明进程运行；就绪检查必须验证数据库和当前模型。Redis/LLM 故障不能阻断同步主模型服务，模型未加载不得伪造成功。

**验收：**模型未加载时 healthz 通过、readyz 失败；LLM 故障时主模型路径仍可服务。

### 7.4 实施保留期与可审计清理（B）

按原始文本、脱敏正文、建议和审计分别定义保留策略，并提供可审计清理命令。删除或匿名化正文时保留最小审计证明。

**验收：**过期数据能被正确处理，审计链仍能表明清理动作发生过。

### 7.5 建立镜像与 Docker Compose（B）

为 API、worker 和 web 构建镜像，使用 Docker Compose 编排 PostgreSQL、Redis、模型跟踪组件及应用服务。`.env.example` 只放变量名和安全示例，绝不包含真实秘密。

**验收：**干净环境可通过一条 Compose 命令启动完整依赖。

### 7.6 建立 CI 门禁（B+C）

依次执行格式/lint、类型检查、秘密扫描、单元测试、契约测试、数据质量与泄漏测试、集成测试、前端构建和镜像扫描。完整模型训练不在每次提交运行，使用固定小模型和小样本做推理回归。

**验收：**故意引入的失败会阻止合并；门禁覆盖既定检查项。

## 本阶段交付物

- JWT/RBAC、结构化日志、`trace_id` 和审计
- 健康检查、Prometheus 指标、保留期/清理机制
- API/worker/web 镜像与 Docker Compose
- CI 检查流水线和失败证据

## 退出门槛

- 一键启动、权限隔离、无正文日志、模型就绪检查和关键降级行为均经验证。
- CI 能阻止质量、契约、泄漏或秘密问题进入主分支。
