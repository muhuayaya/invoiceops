# 阶段 5：批量任务与受控 LLM 辅助

## 阶段目标

在不削弱人工门禁、脱敏和可审计性的前提下，支持 CSV 异步批量分类，并让外部 LLM 只作为低置信度样本的第二意见。

## 开始条件

- 阶段 4 的单条分类、审计和人工复核路径可用。
- LLM 默认关闭；未配置脱敏策略、提供商和预算时不得调用外部服务。

## 实施步骤

### 5.1 配置异步任务与批次状态机（B）

配置 Redis、Celery worker 和批次状态机。批处理从 API 中解耦，以便 API 在任务执行期间保持响应；worker 重启后必须能安全恢复未完成任务。

**验收：**重启后未完成任务可恢复，且不会重复创建业务记录。

### 5.2 实现 CSV 批量上传与查询（B）

提供批次创建、逐行校验、异步分类和状态查询。无效行不应阻塞有效行；结果需展示行号与明确错误原因。

**验收：**混合有效/无效 CSV 中，有效行被处理，错误行可定位。

### 5.3 约束 LLM Provider 契约（A+B）

定义与具体厂商无关的 `LLMProvider` 接口、版本化提示词和严格 JSON Schema。请求仅包含脱敏正文、允许标签定义与必要的最小上下文。

**验收：**fake provider 契约测试能拒绝未知标签和无效 JSON。

### 5.4 建立 LLM 策略门禁与降级（B）

调用前依次检查脱敏状态、标签白名单、功能开关、预算和熔断状态。设置 8 秒超时、最多一次短重试；超预算、超时、未脱敏或连续失败均直接转人工复核。

**验收：**上述所有异常路径均不会得到自动最终决策。

### 5.5 独立保存 LLM 建议（B）

把 LLM 输出保存为独立建议，包含 provider、model、prompt 版本、成本和错误信息。该建议不能覆盖主模型预测，不能成为训练真值，也不能绕过人工复核。

**验收：**建议可审计、可查询，且最终决策仍由复核流程产生。

## 本阶段交付物

- Redis/Celery worker、批次状态机和 CSV 流程
- 版本化 LLM Provider 适配接口
- 脱敏、预算、超时、重试与熔断策略
- `llm_suggestions` 审计记录和异常路径测试

## 退出门槛

- 批次部分失败不会丢失已处理结果或阻塞后续行。
- LLM 只在合规、低置信度场景给出第二意见；任何故障均可靠降级到人工。

## 对应 OpenSpec 任务

`5.1`–`5.5`。
