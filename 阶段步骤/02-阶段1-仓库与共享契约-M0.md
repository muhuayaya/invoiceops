# 阶段 1：仓库与共享契约（M0）

## 阶段目标

建立可协作、可验证的工程骨架，并冻结标签、接口和事件这三类共享契约。完成后，三名成员可以在不反复猜测字段含义的前提下并行开发。

## 开始条件

- 已确认本 PoC 只提供“分类建议 + 路由建议 + 人工复核”，不写回 ERP、不触发付款或解除发票挂起。
- 已确认输入为中文、英文或中英混合文本，且同一工单可拥有多个标签。
- 负责人 A（数据与 ML）、B（后端与平台）、C（前端与质量）已明确。

## 实施步骤

### 1.1 建立目录与忽略规则（B）

创建 `apps/`、`src/invoiceops/`、`ml/`、`configs/`、`tests/`、`infra/`、`docs/` 和 `openspec/` 的约定目录。补充 `.gitignore`，确保生成数据、模型制品、真实 `.env`、本地数据库卷和实验缓存不会进入版本控制。

**验收：**目录清单符合设计文档；敏感或可再生制品没有被 Git 跟踪。

### 1.2 固定开发依赖与统一命令（B）

配置 Python 与前端依赖、锁定文件和统一的开发/检查命令。Python 侧覆盖 FastAPI、PostgreSQL、Redis、MLflow、PyTorch/Transformers 等规划依赖；前端采用 React 与 TypeScript。

**验收：**全新环境能够安装前后端依赖；命令入口可被团队复用。

### 1.3 定义标签、路由和阈值契约（A）

发布 `invoiceops-v1` 标签体系，至少包括：价格差异、数量/收货差异、税务/币种/金额异常、重复发票、缺少采购凭证、付款状态、供应商主数据变更、其他人工复核。为每个标签定义风险、默认主队列、示例和阈值字段，并以 JSON Schema 验证。

**验收：**未知标签、非法风险等级和非法阈值均会被校验拒绝；标签体系与路由规则分离、可独立版本化。

### 1.4 冻结 API 草案与批量模板（B）

定义 OpenAPI v1、统一错误响应、幂等请求头和 CSV 模板。优先固定单条分类、创建批次、查询批次、查询/提交复核、获取当前标签、按请求查询审计以及健康检查端点。

**验收：**OpenAPI Schema 可解析，示例请求有效；前后端可据此独立开发。

### 1.5 共同评审共享资产（ALL）

评审并冻结标签 v1、API v1、内部事件格式和 PoC 验收指标，将结论记录为 ADR。后续任何破坏性变更都需版本升级或三人共同确认。

**验收：**三个共享资产均有负责人、版本和评审记录。

## 本阶段交付物

- 工程目录、依赖锁定与 `.gitignore`
- `invoiceops-v1` 标签/路由/阈值 Schema
- OpenAPI v1 草案、错误规范、幂等规则与 CSV 模板
- 共享契约 ADR

## 退出门槛

- 三名成员均能在本地完成依赖安装。
- 契约测试能验证标签与接口示例。
- 未冻结的接口或标签语义不得进入下一阶段实现。

## 风险与控制

| 风险 | 控制方式 |
|---|---|
| 三人同时改动契约 | 指定单一负责人、以 Schema/OpenAPI 快照守护、变更需共同评审 |
| 把“部门”误当模型标签 | 保持“标签回答问题、路由决定负责人”的分层 |
| 将秘密或训练制品提交仓库 | `.gitignore`、环境变量示例和 CI 秘密扫描 |
