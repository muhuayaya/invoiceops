# 阶段 4：后端领域与持久化

## 阶段目标

实现从单条工单接入到预测、路由、人工复核和审计追踪的后端主链路，形成 M1 的最小垂直切片基础。

## 开始条件

- 标签与 API 契约已冻结。
- 模型运行时至少可加载轻量基线；阶段 3 的主模型可在准备好后替换接入。

## 实施步骤

### 4.1 建模核心领域状态（B）

实现标签、工单、预测、复核、模型版本和审计的领域对象与状态转换，明确哪些转换非法。标签描述问题，路由规则决定主队列和协同队列。

**验收：**非法状态转换在单元测试中被拒绝。

### 4.2 建立可重复数据库迁移（B）

使用 PostgreSQL 建立 `tickets`、`predictions`、`prediction_labels`、`reviews`、`model_versions`、`taxonomy_versions`、`audit_events` 和 `outbox_events` 等核心表。审计事件只追加，不以普通业务接口更新或删除。

**验收：**空库与已有库均可执行迁移；唯一键、外键和审计约束有效。

### 4.3 接入单条分类请求（B）

实现单条工单字段校验、正文长度限制、白名单元数据、语言结果和贯穿链路的 `trace_id`。核心入口为 `POST /api/v1/classifications`。

**验收：**有效文本、中英混合、空文本和超长文本均返回符合契约的结果或错误。

### 4.4 实现幂等与冲突处理（B）

保存幂等键与请求体摘要。相同键和相同请求体返回首次结果；相同键配不同请求体返回冲突，且不得重复写入业务记录。

**验收：**幂等和冲突 API 测试通过。

### 4.5 接入模型、风险覆盖与路由（A+B）

接入统一模型运行时、逐标签阈值、低置信度拒识、高风险人工覆盖及版本化路由规则。供应商主数据/收款信息变更即使模型置信度很高也要进入人工复核。

**验收：**中英混合多标签、低置信度与高风险主数据变更集成测试通过。

### 4.6 提供人工复核 API（B）

实现待复核查询与追加式决策。复核人员可接受建议或增删标签、调整路由并写备注；二次修订须保留完整历史，并将合格反馈标记为训练候选。

**验收：**接受、改标、二次修订、风险排序和训练候选规则均可追溯。

### 4.7 提供审计查询与 outbox（B）

按 `request_id` 记录接入、预测、路由、复核、模型提升和回滚事件，并提供授权范围内的审计查询接口。

**验收：**任一请求可还原有序事件链；业务事实与待发布事件在同一事务中写入。

## 本阶段交付物

- FastAPI 主链路、领域规则与 PostgreSQL 迁移
- 单条分类、复核和审计 API
- 幂等、风险覆盖、版本化路由与 outbox
- 单元、API 与集成测试

## 退出门槛

能够演示一条模拟工单：接入 → 多标签预测 → 队列建议 → 必要时人工复核 → 按请求查询审计历史。
