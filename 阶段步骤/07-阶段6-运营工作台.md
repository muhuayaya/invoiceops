# 阶段 6：运营工作台

## 阶段目标

交付面向运营人员的 React + TypeScript 工作台，使他们能够提交工单、查看结果、处理批次、进行人工复核，并阅读授权范围内的审计与运行状态。

## 开始条件

- 阶段 4 的单条分类、复核和审计 API 可用。
- 如需要批次与 LLM 降级展示，阶段 5 的接口已就绪。

## 实施步骤

### 6.1 建立应用壳与登录态（C）

搭建 React + TypeScript 应用、路由、API client 和登录态管理。受保护页面在用户未登录或无相应角色时不得暴露内容。

**验收：**本地构建成功；未登录访问受保护页面被拒绝或跳转。

### 6.2 实现单条工单提交与结果页（C）

提供中英文本提交界面，展示语言判定、标签分数、主/协同队列、决策状态、模型版本、阈值版本、标签版本与 `trace_id`。

**验收：**多标签响应中的字段完整、准确呈现；低置信度状态不被误显示为已自动结案。

### 6.3 实现 CSV 批次页面（C）

支持上传 CSV、轮询/查询批次进度并展示逐行错误。页面需区分“批次运行失败”与“部分行失败”。

**验收：**混合有效性样例可看到总体进度和每个错误行的原因。

### 6.4 实现人工复核队列（C）

展示按风险排序的待复核工单，支持筛选、接受建议、增删标签、调整路由和追加备注。二次修订必须能看到历史版本。

**验收：**高风险项目优先；改标及后续修订均能从界面查看历史。

### 6.5 实现审计时间线与只读看板（C）

为有权限的人员展示按请求查询的事件时间线，以及错误率、时延、复核积压、LLM 调用/降级等只读运行指标。

**验收：**时间线按事件顺序展示；看板不泄露正文、凭据或超出权限的数据。

## 本阶段交付物

- 工作台应用壳、登录态和受保护路由
- 单条分类、批次、复核、审计和运行看板页面
- 前端构建与关键交互测试

## 退出门槛

运营人员可不依赖接口调试工具完成核心闭环：提交 → 查看建议 → 复核 → 查看审计；批次错误能被明确定位。
