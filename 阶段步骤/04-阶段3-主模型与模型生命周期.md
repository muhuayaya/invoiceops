# 阶段 3：主模型与模型生命周期

## 阶段目标

训练和评估 XLM-R 多标签主模型，建立阈值、拒识、版本注册和回滚能力，使模型成为可替换、可审计的业务组件。

## 开始条件

- 阶段 2 已冻结数据版本、挑战集和统一评估器。
- 轻量基线已有可复现实验结果。

## 实施步骤

### 3.1 实现可复现的 XLM-R 训练（A）

实现 XLM-R 多标签数据加载器、sigmoid 分类头与训练配置，采用带类别权重的 `BCEWithLogitsLoss`。默认文本最大长度 256 tokens，后续只能依据数据分布或实测调整。

**验收：**固定随机种子下的小样本训练可复现；训练配置与数据版本均被记录。

### 3.2 完成首轮训练与误差分析（A）

训练候选模型并分析混淆样例、长尾标签和语言差异。输出训练记录和模型卡，明确数据局限而非包装为生产收益。

**验收：**模型制品、代码版本、数据版本和评估报告可相互关联。

### 3.3 校准逐标签阈值与拒识（A）

为每个标签设置候选阈值与自动接受阈值，加入置信度校准、无标签拒识和冲突组合原因码。阈值必须独立于模型版本管理。

**验收：**低置信度、无标签和冲突标签组合均能产生预期的拒识/复核原因。

### 3.4 建立统一模型运行时（A）

提供统一推理契约，使轻量基线与 XLM-R 可被替换而不改变上层 API 和领域逻辑。运行时负责预处理、模型装载、逐标签分数和版本信息输出。

**验收：**两类模型均可通过同一接口完成推理。

### 3.5 建立注册、准入与回滚（A+B）

实现模型注册、离线准入、`active alias` 和上一稳定版本回滚。关键标签 `SUPPLIER_MASTER_CHANGE` 的召回率不达门槛时，不得提升为 active。

**验收：**提升失败被阻止；回滚后新请求实际使用上一稳定模型。

### 3.6 执行冻结评估与性能测试（A）

在记录明确的验收硬件上使用冻结集进行评估，至少运行 500 次无 LLM 单条推理，记录 CPU/GPU、内存、并发与 P50/P95。

**验收：**如达标，记录 Macro-F1 ≥ 0.80、Micro-F1 ≥ 0.85、关键类 Recall ≥ 0.95、中文/英文 Macro-F1 差值 ≤ 0.08、P95 ≤ 800 ms；如未达标，记录阻塞事实而非伪造通过。

## 本阶段交付物

- XLM-R 训练代码、可复现配置和模型制品
- 模型卡、误差分析、阈值/校准版本
- 统一模型运行时、模型注册表与回滚机制
- 冻结评估和性能报告

## 退出门槛

- 主模型与基线可按相同推理契约替换。
- 当前 active 模型、上一稳定模型及其数据/阈值/标签版本均可追溯。
- 未满足关键风险门槛的模型不能进入 active。
